## Connection 2: Filesystem Abstraction as the Bridge Between the Memory Debate (Memory x Tool Design x Infrastructure)

**Topics:** Agent Memory and Context Management + Tool Design Patterns (Filesystem Abstraction)

**Insight:** The KB documents a sharp debate between filesystem-as-memory (Letta's benchmarks showing 74% accuracy) and database-as-memory (Kevin Gu's critique of markdown drift and governance). Kyle Mistele's filesystem abstraction pattern -- "agents don't need a filesystem, they need something that looks like a filesystem" -- resolves this debate architecturally. You can present filesystem-shaped tools to the agent (leveraging training-data familiarity that explains Letta's benchmark results) while backing them with a structured database (satisfying Gu's concerns about schema, provenance, and drift). The agent gets the interface it performs best with; the infrastructure gets the governance it needs.

**Evidence:**

- Tool Design article: Mistele's key claim: "your tool can look like a normal FS read tool to the agent, but you can use whatever backend you want for the execution logic -- S3, Postgres, Chroma, durable streams, whatever."

**Source suggestion:** Research query: "virtual filesystem for LLM agents backed by structured database." ## Connection 3: The Evaluator Calibration Problem Is a Compaction Policy Problem (Self-Improvement x Memory x Long-Running Agents)

**Topics:** Autoresearch and Self-Improvement + Agent Memory and Context Management + Long-Running Agent Harnesses

**Insight:** The KB documents two seemingly separate problems that are structurally identical: (1) evaluator calibration in autoresearch/GAN-inspired loops -- "the quality of the evaluator determines whether the loop improves or just churns" -- and (2) compaction policy design -- "no standard approach exists for deciding what information is load-bearing versus expendable during compaction." Both are information triage problems: deciding what matters and what can be discarded, under constraints. The evaluator must decide which aspects of generated output are load-bearing for quality; the compaction system must decide which context is load-bearing for the agent's next action. Compaction is evaluation applied to memory, and the same techniques (binary checklists, separate evaluator agents, few-shot calibration) should transfer.

**Evidence:**
